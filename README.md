# 本册自述（`wuyu-web/.workbuddy/memory/`）

> 建立 **2026-11-09**（新项目首日）。**为什么建它**：本项目跨会话、跨 Agent 开发，会话结束即失忆；
> 结论若只留在对话里，等于没发生。本册是「**注入 + 索引 + 现场 + 日志**」的落盘处，**不是知识权威**。

## 一、这里有什么

| 文件 | 角色 | 谁写 |
|---|---|---|
| `MEMORY.md` | **L1 注入层**（每会话自动注入，硬限 8,000 字符） | **手工维护**（不走生成器） |
| `MEMORY-细节.md` | **L2 索引层**（只放指针，不放正文） | 人 + AI |
| `README.md` | 本自述：地图 / 登记规则 / 预算 / 工具 / 生命周期 | 手工 |
| `index.md` | **文件级登记**（`F-NNN`），审计 M 段逐条比对 | 手工 / 刷新工具 |
| `decisions.md` | **ADR**（编号递增、不复用） | 手工 |
| `status.md` | 工作层「**当前现场**」（≤60 行，**不写待办**） | 人 + AI |
| `inbox.md` | **收件箱**（append-only，结算时归并并清空） | 人 + AI |
| `_log_ledger.json` | 日志**台账**（单一权威状态） | `tools/_log_ledger.py` |
| `archive/<日期>.md` | 归档日志（只读） | 归档工具 |
| `automations/<uuid>/memory.md` | 自动化任务的运行记忆 | 自动化 |
| `YYYY-MM-DD.md` | 当日日志（**当天不归档**） | 人 / 自动化 |

## 二、三层分工

| 层 | 文件 | 容量 | 放什么 |
|---|---|---|---|
| **L1 注入层** | `MEMORY.md` | 硬限 **8,000** / 预算 **7,800** 字符 | 可执行事实 + 踩坑结论，**一行一条**；超了尾部**静默消失** |
| **L2 索引层** | `MEMORY-细节.md` | 上限 **20,000** 字符 | **只放索引**（主题 → 去哪找），正文住 `docs/` |
| **L3 日志** | `YYYY-MM-DD.md` | 无硬限 | 当日过程记录，按时间戳分节 |

> 判定一句话：**「能一行说完吗？不能 ⇒ 拆：结论进 L1，论据进 L2 / `docs/`。」**

## 三、登记规则

- **`F-NNN`**：文件级登记号，`index.md` 一行一个文件，**一文件一行**、ID **永不复用**（退役行保留 ID 并标注原因）。
- **表格列**：`| ID | 路径 | 关键词 | 行数 | 最后验证 |`，路径相对本册（项目根文件写 `../../`）。
- **行数列**：填**实测** `wc -l`。两类填哨兵 `—`：① **每轮都会变**的文件（`_log_ledger.json`、`inbox.md`、`status.md`）；② 尚未生成的文件 —— **必须在关键词里注「待复测」**。
- **「最后验证」**= 本行内容（路径 / 关键词 / 行数）最后一次被核对的日期；刷行数**就是**一次核对，日期同步更新。
- **单元格内不得出现未转义的半角竖线**（`|`）—— 两个解析器都按 `[^|]` 收单元格，出现即**整行不可见**。
- **审计 M 段怎么查**：取 `index.md` 登记路径集合 → 逐个 `ls` / `os.path.exists` 比对磁盘 → 回报「缺失 / 未登记多出 / 行数不符」。
  ⚠️ **0 条可比对 ≠ 通过**（空集合必须报「跳过」，不许报绿）。
- **新建 / 归档纳管文件后，同一次结算内更新 `index.md`**。

## 四、容量预算

| 对象 | 预算 | 超了怎么办 |
|---|---|---|
| L1 `MEMORY.md` | 硬限 **8,000** / 预算 **7,800** 字符 | **下放优于删除**：整条原文移进 L2 / `docs/`，L1 留一行指针 |
| L2 `MEMORY-细节.md` | **20,000** 字符 | 把最老批次正文外置到 `docs/memory/`（**不放 `archive/`**，那里退出检索池） |
| `status.md` | **60** 行 | 完成项移出；结论下放 |
| `index.md` | 200 行 | 按类别分区 |
| `decisions.md` | 100 条 | superseded 的移入归档 |
| `inbox.md` | 结算后**必须为空** | 非空 = 上次结算未完成 |
| L3 日志 | **不设体积阈值** | 判「有没有提炼」看台账状态机，不看体积 |

> 🔴 **不允许为腾空间去调预算常量**：8,000 是宿主行为，改常量只是把截断往后挪。

**三档处置**：① 草稿 ≤ 余量 ⇒ 直接写；② 贴边（超 ≤200 字符）⇒ **先压措辞**（不许动路径、不许动阈值数字）；③ 压完仍超 ⇒ 才外置整章。

## 五、工具用法（住项目根 `tools/`）

> ⚠️ `tools/` 由他人并行编写中，**以下为规划名**，以磁盘实际文件为准；缺哪个就是还没落地，不要假装跑过。

| 脚本 | 一句话 |
|---|---|
| `_mem_check_all.py` | 统一入口，按固定顺序跑全部记忆闸门 |
| `_mem_audit.py` | 分层审计（体量 / 编号 / 结构 / 指针 / 索引差集 / ADR） |
| `_l1_token_guard.py` | 证明手维护 L1 改完**没丢标识符与数字**（`snapshot` / `check`） |
| `_mem_bridge.py` | 把 L1 逐字节写到「会开工的目录」并校验一致（**注入桥**） |
| `_log_ledger.py` | 日志台账状态机（`--scan` 对账） |
| `_log_distill.py` | 蒸馏前置地图：标题大纲 + 低覆盖候选行 |
| `_index_refresh.py` | 刷新 `index.md` 行数列（真变动才盖日期） |
| `push_memory.py` | 本册 add / commit / push |

> ℹ️ **为什么要注入桥**：宿主注的是「**会话工作目录**下的 `.workbuddy/memory/MEMORY.md`」，而工作目录常是**带时间戳的子目录** ⇒ 它下面没有记忆文件 ⇒ **零注入、且不报错**（开场「失忆」却查不出原因）。

## 六、生命周期

```
当日日志 L3 ──蒸馏──▶ L2 新增一章 ──压缩──▶ L1 一行
```

1. **记**：会话中的候选结论**先追加进 `inbox.md`**（append-only），不直接改 L1 / L2。
2. **蒸**：结算时逐条归并 —— 值得留的进 `docs/`（正文）＋ `MEMORY-细节.md`（指针）＋ `MEMORY.md`（一行结论）；不值得的丢弃。
3. **压**：L1 超预算时按「下放优于删除」处理，**不删内容，只改加载时机**。
4. **归**：日志处理完打 `distilled`，审计过打 `verified`，归档后打 `archived`（**单向**，`_log_ledger.json` 由工具维护，**勿手改**）。
5. **清**：`inbox.md` 清空、`status.md` 完成项移出、`index.md` 同步、体量复算并回读。

**降级**：热（L1）→ 温（L2 / `docs/`）→ 冷（`archive/`，只读、不回写）。**任何一层都不删内容。**

## 七、独立仓与 L1 守卫（⚠️ 必读）

- **本册是独立 git 仓**（`git init -b main` 建于 2026-11-09），**与主仓分开提交**；主仓的提交命令**不带**本目录。
- **L1 有令牌守卫**：`MEMORY.md` 手维护 ⇒ 手改就会丢规则。改 L1 的**固定顺序**：
  1. **改前** `python3 tools/_l1_token_guard.py snapshot`（存基线）
  2. 改
  3. **改完** `python3 tools/_l1_token_guard.py check` —— 必须报「**丢失 0**」
  > ⚠️ **顺序不可颠倒**：反过来等于把改动后的状态当基线，丢失永远测不出来。
- 实在要删某个标识符 ⇒ **显式豁免并注明「信息还在哪」**，否则 `check` 报丢失就是真丢了。
- 本册忽略 `*.bak-*`、`*.base-commit-*`、`.DS_Store`（见 `.gitignore`）；快照 / 备份不进仓。

## 八、读取纪律

- 开工读：L1（自动注入）→ `status.md` → `inbox.md`（非空则先补上次结算）。
- **L2 是索引层，不整篇读**；`archive/` 默认不读，只在追溯时读。
- 单个任务最多打开 5 个正文文档；不够时**先查索引缩小范围**，禁止逐文件翻找。
